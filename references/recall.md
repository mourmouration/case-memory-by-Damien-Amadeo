# Режим RECALL – поиск по опыту всех дел

Справочный файл скилла `case-memory`. Применяй правила совместимости из SKILL.md; операции Claude необязательны и используются только при наличии инструментов. Читается при RECALL. Режим отвечает на вопрос «что у нас уже было по теме, норме или ситуации» без загрузки каждого дела целиком. Он только читает.

## Шаг 1 – Доступ

Определи MEMORY_DIR (SKILL.md, «Доступ к памяти»). В облачной сессии получи копию `lessons.md`, `index.md` и карточек `projects/` (`device_stage_files`, до 50 файлов за вызов); файлы `sessions/` – только если понадобится третий слой.

## Шаг 2 – Ключи

Из запроса извлеки 3–8 ключей и расширь их вариантами записи:

- норма в разных написаниях: `61\.2`, `ст61.2ЗоБ`, «подозрительн»;
- синонимы и смежные понятия: «зачёт» → `сальдир`, `предпочт`; «неустойка» → `пени`, `ст\. ?333`;
- теги из словаря SKILL.md – как уточняющие ключи, а не как единственные: один тег категории совпадает с каждым уроком этой категории.

Ключ – слово, основа слова или регулярное выражение. Регистр и «ё/е» скрипт не различает.

## Шаг 3 – Поиск

```bash
python3 <skill-dir>/scripts/memory_tool.py recall DIR ключ1 ключ2 … [--sessions] [--all-sections]
```

Скрипт ищет по слоям и ставит выше находки, где совпало больше ключей:

1. `lessons.md` – главный источник: уроки уже обобщены и с причинами.
2. Карточки `projects/` – только разделы «Актуальные правовые позиции» и «Что не работало»: это проверенный опыт. `--all-sections` снимает ограничение.
3. `sessions/` – если первые два слоя пусты или задан `--sessions` (подробности по конкретной находке).

Файлы из раздела «Архив» `index.md` в поиск не входят.

Обычный `grep -i` по кириллице зависит от локали и в локали POSIX молча ничего не находит; если скрипт запустить нельзя, ищи с `LC_ALL=C.UTF-8` и раздел карточки определяй чтением.

Если в `0.3. Memory/` ничего нет и в сессии есть `mcp__memory__*` – посмотри `/areas/` встроенной памяти: дело могло обсуждаться только в обычном чате. Находку оттуда помечай «из встроенной памяти, в карточку дела не перенесено».

## Шаг 4 – Результат

Группируй по сути, а не по файлам. Сначала уроки, затем позиции из карточек. По каждой находке:

> **[Вывод / позиция]** – дело [название], [дата]. Причина: [норма / акт]. Статус: [принята / сработала / отклонена судом / снята / не сработало]. Источник: `0.3. Memory/<файл>`.

- Статус берётся из записи. Если в записи его нет – пиши «статус не указан», не домысливай.
- Пометки скрипта «УСТАРЕЛ» и «старше года» переносятся в ответ. Всё, что опирается на норму, которая могла измениться, помечай «требует проверки актуальности редакции и практики»: память фиксирует состояние права на дату записи.
- Находка с одним совпавшим ключом-тегом – шум: в ответ не идёт.

Ничего не найдено – так и скажи: «В памяти по [запросу] ничего нет». Пустой результат не подменяется общими рассуждениями о теме.

## Шаг 5 – Следующий шаг

Одной строкой, по ситуации:

- нашлась позиция, нужная в текущем деле, – «загрузить карточку дела [X] целиком (LOAD)?»;
- уроки противоречат друг другу – «уроки расходятся, предлагаю разобрать в CONSOLIDATE».
